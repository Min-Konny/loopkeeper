# 村の施設カード統一 — 0.6.126

対象は村の17施設・63段階レシピです。初期施設のアトラス切出し画像は内側の枠を消し、住宅・専門施設の直接画像だけに枠を付ける別のCSSがあり、枠の有無と画像領域の高さが異なっていました。カードも上揃えで、文量・材料数・専門施設の別列ボタンによって高さと操作位置がずれていました。

共通の外枠一つに背景と角丸を集約し、内側の画像の枠を外しました。PCは84px、狭幅は72pxの正方形領域で、直接画像は縦横比を維持し、アトラスは既存の切出しを維持します。元の画像・段階・固有の輪郭は変更しません。概要／材料・数値／操作の3段を自然な高さで配置し、隣接カードはsubgridの行を共有。未対応ブラウザは通常gridにフォールバックします。固定のカード高や文字の切捨ては使いません。

材料チップは工房と共通の関数を使用。必要数・所持数・不足数の計算、費用の取得や支払いは変更せず、資源名・数値を安全な文字列として表示します。村では12pxの文字と折返しを使い、大きな在庫数が材料名の幅を奪わないようにしています。専門施設の作業リンクと建設・表示切替は同じ操作列に集約し、主要ボタンは44px以上の高さを確保。施設の効果や解放条件、建設時間、経済、難度は不変です。

関連監査では工房の材料表示を共通化しました。サイドバーの施設要約と戦闘中の小さな施設HUDは建設カードと役割が違うため、別のコンパクト表示を維持しています。全画面の別テーマ化はしていません。

合成セーブを使い、PC1280/390px/320pxで63段階、未建築・途中まで建築済み・最大段階、材料充足/不足、通常/低モーションを確認。長い名称・説明・大数値、キーボードfocus、分類とタブの切替、画像欠損/遅延、実際の建設、支払い済み作業と予約の保存再読込も確認します。旧UIのGit保存済み描画と同条件の比較画面を保存。実セーブと実機スマホは使用していません。

この確認中、現在の正当な発見済み項目が201件になると、保存側の古い最大200件の制限で拒否される既存の境界不具合を確認しました。IDの許可リストと重複禁止を保ったまま、上限を現在の定義ID数＋3つの機能IDへ合わせています。発見履歴を切り捨てず、古いセーブ・201件を含む正当なデータを保持し、未知ID・重複・不正な配列は引き続き拒否します。発見履歴から所持品や報酬を推測付与する処理はありません。保存形式そのものは変更しません。

自動製作切替スクロール9条件、訓練目標current+1の6条件、予約編集3条件、入力保持3条件の回帰も実施。訓練中の仲間の武器が初期画像に固定される別の表示課題は、この更新では未修正です。剣6素材の戦闘表示は維持します。
